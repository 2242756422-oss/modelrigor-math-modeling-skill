# Data Quality and Preprocessing Playbook

本文件仅在数据质量、统计/ML或观测过程成为当前问题的实质风险时加载。它提供诊断与候选方法，不设置固定缺失率阈值、固定随机种子或固定预处理流水线；最终处理必须由数据生成过程、领域含义和下游evaluator决定。

## 1. 先识别观测机制

优先回答：观测单位是什么、样本如何产生、时间/空间/个体是否相关、训练与目标总体是否同分布、标签何时产生、哪些变量在预测时真实可得。之后再处理缺失、异常和编码。

缺失应区分：MCAR、MAR、MNAR、结构性缺失/不适用。不能仅按缺失比例自动删除变量；需同时考虑变量重要性、样本量、缺失是否携带信息、可否外部校准和插补不确定性。

异常应先区分：录入/单位错误、测量故障、重复/逻辑冲突、真实极端值、统计离群。真实极端值不能因“离群”自动删除；必要时采用稳健损失、变换、分层或敏感性分析。

## 2. 处理必须与模型和切分一致

- 任何从数据估计的预处理参数（均值方差、插补器、PCA、特征选择、目标编码、阈值、分箱边界等）只在训练折拟合，再应用到验证/测试折。
- 时间序列按时间因果顺序切分；组/个体相关数据优先group-aware split；空间外推需空间阻断或外推型验证。
- Target Encoding只在确有必要时使用，并采用fold-local/out-of-fold或nested流程；不得用测试标签或全量标签统计量。
- 标准化只在模型/距离度量/正则化确实需要时进行；树模型通常不因形式统一而强制缩放。
- 类别编码由变量语义、基数、顺序性和目标模型决定；高基数名义变量不能机械Label Encoding后假装产生顺序。
- 特征工程应有领域含义或可检验的预测价值；衍生特征的计算窗口、可用时点和单位必须防止未来信息泄漏。

## 3. 时空与分布风险

检查偏态、长尾、零膨胀、删失/截断、类别不平衡、共线性、分布漂移、时间不连续、空间缺口和周期异常。处理前先判断这些结构是否是现象本身，而不是“脏数据”。

多重插补、重采样、变换、稳健回归、降维或异常检测都属于候选方法；若它们会显著改变结论，应进入uncertainty/sensitivity或独立验证，而不是只写在预处理说明里。

## 4. 最小可审计输出

数据处理应能追溯：原始来源/版本、行列与单位、关键质量问题、处理理由、fit/transform边界、受影响样本、随机性与seed（如适用）、处理后数据hash、与模型输入字段的对应关系。代码可一键复现，但不强制特定语言、模块名或固定seed=42。

## 5. 与v5现有Gate的关系

- `Domain Professionalism`决定哪些异常/缺失具有真实业务或物理意义；
- `Model Contract`记录observation unit、DGP、split、leakage controls和generalization target；
- `Uncertainty Budget`记录预处理选择对结论的影响；
- `Result Registry`只登记经过正确预处理和evaluator产生的可追溯结果；
- `Adversarial Reviewer`重点攻击泄漏、未来信息、全量fit、分布漂移和因预处理引入的假稳定性。
