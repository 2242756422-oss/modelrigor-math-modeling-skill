# 高质量高效研究协议（v5.1）

HIGH_QUALITY_EFFICIENT是执行策略，不新增科学状态机。FULL_RESEARCH和KEY_DECISION_ONLY改变分工，不改变核心质量。

## 一条权威链

Question/Model Contract → 真执行与输出 → Result Registry → Claim–Evidence → 正式Figure/Table → 正文。AI负责领域理解、方程/约束、推导、算法选择、解释、图表架构与实质审查；Python负责来源取值、哈希、状态、编号、清单、算术与影响范围。科学问题只在首次解决或相关依赖变化时重审。

## 阶段与工件

建模阶段6个工件：question_contract、question_plan、adaptive domain_model_map、model_contract、assumption_ledger、adaptive uncertainty_budget。检查项由activate-domain自动派生，不适用专业不要求回答。DRAFT允许缺正式结果/审稿；小原型明确标注PROTOTYPE，不用于论文结论。
prepare-stage solve仅补result_registry、conditional_gates、claim_evidence_map；需要外部依据时补literature_to_model_map。develop仅补figure_candidates、table_portfolio、visual_semantics、research_review；handoff按需。冻结manifest由程序生成，不提前造空冻结表。
新路径不要求content_units、evidence_promotion、competitive_development、quality_assessment、resource_consumption和五份reviewer报告。对应科学内容没有删除：实际正文、核心风险、图像和科学证据由一份验收审查；资源调用可在真实run receipt记录输入/代码/输出，不重复填管理台账。

## 增量与预算

impact按模型/evaluator与result→verification receipt→code/input/output依赖标出结果、主张和图；--apply只失效相关快照/下游。改变核心模型要重新验证，不由文件名“presentation”豁免。改科学主张强度需Claim/Gate复检；纯措辞/图例只检查本处与最终布局，不重跑实验。
L1先直接/精确路线和代入边界；L2先结构化原型再正式精度/辨识/主风险；L3加强分解、接口传播和关键失败攻击。Depth仅指导实际投入，不制造Benchmark、页/图/公式数。
没有实测Token数据不报节省率。可量化当前阶段文件数、扫描候选数、重复全量审查调用数、运行时间；这些是代理指标，不证明额度或论文质量。

## 兼容

CLI新问题默认此策略；已有无profile或LEGACY_FULL项目保持旧布局。显式迁移只在副本进行，真实验证缺口标NEEDS_SUBSTANTIVE_REVIEW，不能把旧PASS自动认定有效。
