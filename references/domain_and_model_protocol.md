# 领域与模型协议

共同核心：题意/量词/输入输出一致，数学闭合和量纲，假设/适用边界与主要失效风险。scripts/efficient.py按领域激活专业检查，混合题可多选，不要求所有题回答相同14项。

`audit_model_contract`只查结构/一致性，返回无问题不是数学良置性证明。方程数等于未知量数仍可能矛盾、相关、无解或多解；病态也不能靠计数排除。在已有core_review与推导中按主风险核存在性/唯一性/稳定性、初边界、独立约束、可辨识性或离散稳定性；不要求所有问题完整存在唯一性定理。不能自动证明者明确NOT_VERIFIED/适用限制；未解的核心风险进入现有P0，不以填满字段放行。保留便宜原型与迭代，并从这些失败条件中主动找结构改进，而不是因成熟模型存在就停止研究。

- 物理工程：守恒/耗散、参考系与状态顺序、控制关系、初边界、观测、参数物理意义；离散、稳定、稳态窗口与数值精度按风险验证。
- 运筹：决策信息可得性、变量/可行域/目标、分解是否保持目标、硬约束与部署；可行最好值不冒充全局最优，合法界/证书按主张触发。
- 统计：数据生成与观测单位、识别假设、相关/混杂/选择机制、估计、不确定性与稳健性。纯推断不机械要求ML切分。
- ML：分组/时间切分、训练内预处理、泄漏、泛化目标、公平比较、统计评价与解释。
- 理论：定义、量词、必要/充分条件、推导/证明、退化/不可辨识与反例。
- 直接计算：关系、单位、代入、边界；不强加优化目标、随机seed或复杂算法。

模型迭代：理解领域 → 初始结构 → 便宜算例/极限/小原型 → 修订 → 生产求解 → 深验证。正式Model Contract是当前模型唯一权威；研究笔记记录方案理由，不在多处重复维护同一方程。结构创新优先找不变量、解析消元、变量投影、对称、可达性、可分解结构、可辨识性与信息约束；必须说明收益、成立条件和失败反例，不要求创新数量。
一次core_review记录实际核查、证据、未决风险和限制。新增层需数据/辨识支持；外部文献必须进入明确模型对象，不借背景引用闭合模型。未解决领域P0阻止生产求解及冻结；小原型不能充当生产证据。

## 扎实建模与有依据的改进

在已有Model Contract与研究正文中形成可重建的链：领域机制/理论 → 数学对象和变量单位 → 假设如何进入核心方程/约束/目标 → 参数来源与辨识 → 可解性/唯一性/稳定性及适用条件 → 匹配结构的求解 → 验证与可信范围。算法名称或软件包不是模型；复杂研究不能只留最终公式和算法简介。

公式分清成熟理论、自行推导、经验拟合和近似。成熟理论注明来源与适用条件，不重证常识；关键自推步骤说明所用假设与逻辑；经验关系给数据依据；近似给成立条件和误差影响。只保留在模型、求解、验证或解释中有任务的公式；必要的推导、命题/反例、分解和误差分析由真实数学难度决定，无数量要求。

创新从具体困难出发：常规方法是否足够，不足影响精度、可行性、效率、稳定性、解释还是决策；先找更简单路线。准备主张的改进须有“困难 → 基线不足 → 改了什么 → 成立依据 → 实现/实际结果 → 对口验证 → 结论边界”。等价变换用推导和解一致性，辨识改进核观测条件，新约束看可行/决策变化，预测改进看泛化，机理改进看物理/数据；不机械Benchmark/消融。

充分利用守恒、不变量、单调、凸性、稀疏耦合、对称、投影或可分解结构。成熟方法的合理适配可以有价值，但不能冒充原创算法。识别改名、并列算法、无作用模块、随机波动当优势、数值观察当定理和复杂性无收益；先查理论下限与基线是否已足够。少数核心困难构成全文主线，其他问复用成熟模型，不人为限创新数，也不要求每问创新。

核心对应只追科学关键位置：正文方程/约束/参数 → evaluator或实际求解实现 → 输出/验证 → Claim。检查约束真的实现、优化方向/目标及单位相同，关键假设变动重新核适用条件；不逐行注释全程序，不新建公式/创新评分台账。
